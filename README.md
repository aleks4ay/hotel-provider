# hotel-provider
Part of Hotel microservices

## Liquibase migrations
- Переливка осуществляется при запуске приложения
- Перелитые данные повторно не заливаются

## Testes

- Для тестирования был добавлен профиль `@ActiveProfiles("test")` и добавлен файл с настройками `application-test.yml`.
  Настройки будут браться из основного файла `application.yml`, потом перезатираться взятыми из `application-test.yml`.
- В конце еще настройки подключения к БД будут перезатерты данными, полученными от контейнера
    - "spring.datasource.url", sqlServerContainer::getJdbcUrl
    - "spring.datasource.username", sqlServerContainer::getUsername
    - "spring.datasource.password", sqlServerContainer::getPassword

## Roles
- Доступ к эндпоинтам на редактирование будет только у тех, кто имеет роль hotel_provider
- Доступ к эндпоинтам на чтение будет только у тех, кто имеет роль hotel_data_reader
- После регистрации идет запрос на получение роли на чтение

## Управление
- Есть зарегистрированные в Кейклоаке юзеры с ролью hotel_provider
  - они подтверждают регистрацию. Для новых добавляется запись в кейклоаке (вручную или автоматически)
  - вносят новые комнаты и отели через UI
  - временно блокируют комнаты для ремонта и т.п.

## В БД кроме данных о комнатах и отелях должны быть:
- данные о клиентах (логин соответствует тому, что в кейклоаке): с какими отелями они работают. Данные по комнатам отдавать только для этих отелей. И какие комнаты они избегают
- история заказов с данными посетителя и клиента. (ФИО, дата со временем события, событие: BOOK?, BEGIN, BREAK, CANSEL, END. Оплата не здесь для провайдера)
- рейтинг бронирования? чтобы отдать другому клиенту на перебронирование, у кого рейтинг выше
- перечисления от клиентов за завершенные заказы, раз в 5 дней
